Encrypted vault format notes

tagsipfs-sync, formatupdated2026-10-01

Root versions

A version 1 root is plaintext. The current tree refuses it on read: the plaintext reader was removed when the encrypted format landed, so nothing in this build can turn a 0.2.0 publish back into files.

A version 2 root holds current/ (encrypted files under opaque names in two-character prefix folders), manifests/ (one encrypted history copy per publish), manifest.enc and keyslots.json.

Manifest history names

History copies are named <16-digit sequence>-<rootCID>.enc. A development build wrote <rootCID>.enc without the sequence; those still read, and the restore list sorts them last because their sequence is unknown.

Key slots

The key-slot file is public. It holds the wrapped vault content key under each device's Argon2id-derived slot, so anyone who obtains the CID sees how many slots exist and at what cost, and nothing else.

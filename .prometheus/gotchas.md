## 2026-10-06 — shared-node read-after-write lag (observed once)

An e2e S1 pull reported `integrity-failed <file>: the blob could not be read from the node` for a blob the publish had written seconds earlier (gateway read path). The same suite passed before and after with no code change. Reading: transient read-after-write visibility lag on the shared kubo node/gateway. The e2e suite deliberately does not retry around it (a flake fails the run with the reason printed). If this recurs, consider a bounded re-resolve/backoff on the first read of a just-published root — but only with observed recurrence.

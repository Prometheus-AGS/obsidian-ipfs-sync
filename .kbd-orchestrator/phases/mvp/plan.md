## Encryption design (goal 7; built in changes 6–7, reviewed by security-reviewer before release 2)

- **Vault content key (VCK):** 256-bit random, generated once per vault. Never stored in plaintext.
- **Key slots:** the VCK is wrapped (AES-KW or AES-GCM) under a key-encryption key derived from the passphrase with Argon2id (@noble/hashes). Default parameters are m=19 MiB, t=2, p=1 (OWASP minimum, sized for mobile WebView). The parameters and salt are stored in a plaintext `keyslots.json` in the MFS root. Changing the passphrase rewraps the slot; content is not re-encrypted. The slot list is where SPAKE2/UCAN device slots attach later.
- **Content:** a per-file key from HKDF(VCK, file-id). AES-256-GCM over 8 MB segments (native WebCrypto). Each nonce is a random 96-bit value per segment. The AAD binds file-id, segment index and a final-segment flag, which blocks truncation and reordering. This aligns with the existing 8 MB chunking, so the >32 MB path encrypts per chunk.
- **Names:** node-side paths are `current/<2-char prefix>/<base32 HMAC-SHA256(name-key, vault path)>`. Plaintext paths exist only inside the encrypted manifest.
- **Manifest v2:** manifest v1 fields (plaintext sha256 drives delta detection) are encrypted under the VCK as `manifest.enc`. The only plaintext pointers are the root CID and `keyslots.json`.
- **Fail closed:** a wrong passphrase, a GCM auth failure or a missing segment aborts that file's pull with an error. Nothing partial is written to the vault.
- **Deliberately not hidden:** file count, approximate sizes (no padding in MVP), publish timing, and network access patterns (DHT). These are documented in DESIGN.md §8. Size padding and private swarm/relays are deferred.
- **Rejected alternative, WNFS (rs-wnfs WASM):** it hides tree structure and adds a versioned private forest, but it needs the WASM toolchain that docs/003 defers, plus a much larger bundle for mobile. Opaque names plus an encrypted manifest cover MVP's confidentiality need.
- **Format:** encryption is always on from change 6 onward. Manifest v1 (plaintext) is dev/test-only, and nothing reads v1 after change 7, because no real vault is published before then (release 1 uses test vaults only).

## Trade-offs, cuts and deferrals (explicit)

- **T1 (revised): release 1 is plaintext and fixture-only.** It ships before encryption, so the code refuses non-fixture vaults until mvp-06 (pre-encryption rule). v0.2.0 is therefore a demo of sync mechanics, not something you can use on your notes. The first release usable on real notes is v0.3.0. The alternative, encryption before the plugin, puts the first Obsidian-visible release at 7 increments.
- **T2: PGlite ships in the CLI only.** Bundling PGlite WASM into `main.js` for mobile WebView is unproven. The plugin is not wired to a store in MVP.
- **T3: mobile stays unverified** unless the optional mobile attempt in mvp-10 runs. The WebView-safety evidence otherwise is the `src/` grep, bounded per-segment memory by construction, and pure-JS Argon2id with m=19 MiB.
- **T4: encryption metadata leakage.** File count, sizes, timing and access patterns are visible to the node and the DHT. Padding and private relays are deferred.
- **T5: a single shared passphrase is the only device-onboarding path.** A lost passphrase means lost data; there is no recovery by design. SPAKE2 pairing and UCAN device slots attach to `keyslots.json` in a later phase.
- **Schedule cost:** 10 increments (about 20h of 2h slices) against revision 1's 8. Encryption is +2, and the endpoint/auth model enlarges mvp-01 (split point noted).
- **Deferred (not MVP goals):** UCAN/ucanto (cand-004), SPAKE2 (cand-005), DIDComm (cand-007 rejected), OS keychain (cand-006; MVP secrets come from plugin settings, env or prompt), the Q7 control center, pgvector, the graph adapter, CAR/@ipld/car (cand-002), the pure-TS tar reader, WNFS, and size padding.
- **Conflict with docs/011 Q6:** 011 calls `didcomm-node` maintained; analyze found it stale (2023-05). Moot for MVP.

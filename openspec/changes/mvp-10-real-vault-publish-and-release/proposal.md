## Why

The encrypted loop is proven against fixtures and the staging node (mvp-06 through mvp-09), but phase goals 6 and 7 are not met until the operator's real vault — a vault with nested vaults, 1.5 GB on disk, about 4,824 files / ~1.0 GB after default exclusions (read-only scan, 2026-10-05) — has been published encrypted from inside Obsidian and reproduced into a fresh vault with zero content mismatches. This change is that proof, plus the documentation sync the code has outrun, plus Release 3 (v0.4.0).

The uncomfortable parts:

- **The publish is operator-run, and an agent must not run it.** The 2026-10-05 handoff records that the permission layer denied an agent upload of the real directory and the operator then said not to publish it. Every task that touches the real vault or the shared node with real content assigns the action to the operator; ipfs-engineer prepares and verifies but does not execute the publish or the pull demo.
- **The vault holds a leaked OpenAI key.** Encryption removes the "public by CID" exposure but does not undo the leak; the key is rotated regardless, as an operator task outside the repository, before the publish.
- **The vault churns under the publisher.** `.llm-wiki/` holds 1,461 files that change while Obsidian runs, and the whole-file read path (files ≤32 MB, the common case) does not raise `FileRemovedDuringReadError`: a small file deleted between scan and hash aborts the publish instead of being skipped (`cli/node-host-bridge.ts:122` and `src/plugin/obsidian-fs.ts:97-102` never map the missing file; `src/sync/diff.ts:89` would skip it if they did — flagged during the mvp-08 repair, `.kbd-orchestrator/phases/mvp/execution.md:98`). With the real vault this will fire during the demo. The hardening is in this change, before the operator run.
- **The demo publishes real metadata.** File count, sizes, timing and access patterns of the operator's own vault become visible to the node and the DHT (T4, accepted at plan time). The demo record makes that a one-time informed choice, not a side effect.

## What Changes

- **Publish-during-churn hardening (ipfs-engineer).** Both hosts raise `FileRemovedDuringReadError` when a file vanishes under a whole-file `read` (CLI: map ENOENT in `cli/node-host-bridge.ts` `read`; plugin: route `readAll` through the existing `readBinaryOrRemoved` in `src/plugin/obsidian-fs.ts`). The existing skip path in `src/sync/diff.ts` and `src/sync/encrypted-transfer.ts` then treats a removed small file exactly like a removed large one: skipped this run, picked up next run. No engine changes.
- **Lighter operator gate, before any publish.** A secret scan of the real vault (operator-run; ipfs-engineer prepares the procedure and the list of the 36 secret-like note names from the earlier scan for adjudication) and the OpenAI key rotation. The pre-encryption rule is gone — encryption is unconditional since mvp-06 — so the gate is about what the operator knowingly encrypts and uploads, not about plaintext exposure.
- **Real-vault round trip from Obsidian desktop.** The operator publishes the host vault from inside Obsidian; wall time, bytes, file count and the root CID are recorded. The operator pulls into a fresh vault in Obsidian; counts and sha256 are compared against the source vault across the published set, with 0 mismatches as the acceptance bar. Every skipped file (read cap, changed- or removed-during-read, dangling symlink, exclusion) is named in the record so the count reconciliation is exact. The mvp-08 history store listing both operations is part of the evidence. mvp-09's `pnpm test:e2e` green run is cited as supporting goal-6 evidence, not re-run.
- **Root decision (recorded in design.md).** The publish reuses `/obsidian-vault-sync/real-obsidian`, adopting the keyslots/passphrase pair the aborted run left behind: the passphrase file already exists locally (`/Users/gqadonis/.ipfs-sync-secrets/obsidian-real.pass`), so reuse keeps one credential. The adopt path (local slot copy + node `keyslots.json` + no manifest + no local state) is proven on a scratch root first, because `init` refuses a non-empty root (`cli/init-command.ts:66-71`) and the publish-side resume behaviour for this exact state is unverified.
- **Documentation sync (documentation-specialist).** DESIGN.md §4 (config model, gateway reads, manifest v2, the CLI replacing the §4.4 scripts) and §8 (encryption; what is not hidden), README and CHANGELOG. README currently claims Release 2 "is not cut"; v0.3.0 shipped on 2026-10-05 — the docs are reconciled with reality and then extended with v0.4.0 and the demo's observed numbers.
- **Release 3 (v0.4.0) (release-deployment-lead, sole publisher).** Version bump in `manifest.json` and `package.json`; a GitHub pre-release on `Prometheus-AGS/obsidian-ipfs-sync` carrying `main.js`, `manifest.json`, the CLI tarball and a SHA-256 checksum file; release notes that open with what the release can and cannot do and carry the AI-layer gate sentence (below); the release demo procedure and its observed result in the release record. A tag or a workflow run alone is not a release (phase plan, release definition).
- **One batched approval for all outward steps.** The operator asked to reduce question count. The exact commit(s), tag `v0.4.0`, branch and tag pushes, and the GitHub pre-release command — with the full asset list, checksums and release-notes text — are presented in ONE approval gate. On a yes, the steps execute without further questions; any item the operator strikes stays unexecuted and is reported as such. The publication receipt is produced only if a first-party page with absolute asset URLs exists (Release 2 left it pending; same expectation here).
- **AI-layer gate, carried from this change's README.md (binding).** Phone embeddings are opt-in; an iPhone run loading PGlite and the ONNX model together (peak memory recorded) is an acceptance gate before any airplane-mode or on-device-AI claim. The release notes task's Verify greps that no such claim shipped without the run.
- **Cleanup on confirmation only.** `publish-real-20260929` (the staging tree left on the node) is removed only after the operator confirms, once the round trip has passed. The mobile attempt is optional: if it runs, its outcome is recorded; if not, mobile stays unverified (T3) and the notes say so.

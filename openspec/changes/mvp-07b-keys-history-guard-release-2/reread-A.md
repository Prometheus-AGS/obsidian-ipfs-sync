## The 5 most important changes

1. **A lost race on rewrap or prune poisons the shared MFS tree, and `keys discard` does not repair it (tasks 1.3, 1.4, 1.5; design 4 lines 54-56).**
   The plan treats a lost rewrap race as a local dead end: `tasks.md:18` and `design.md:56` say `keys discard` "touches nothing on the node". But the loser has already written its `keyslots.json` into the shared working tree (`design.md:46`, step `file-written`). 07a found exactly this class of defect as D-1 and fixed it for `manifest.enc`: `publish-commit.ts:182-187` calls `withdrawManifestFile` when the name re-check throws `NameMovedError`, and `publish-commit.ts:204-212` puts the previous bytes back only if they equal the file inside the root the name moved to. Without the same step, the winning device's next publish or pull finds a `keyslots.json` that is not its copy: `vault-keys.ts:211-213` (`openWithCopy`) throws `vault-mismatch` for every publish, and `createSnapshotVerifier` checks `keyslots.json` equals the copy (`read-back.ts:113-125`). Change: the `republish-root` primitive (1.3) gets a withdrawal step on `NameMovedError`. For rewrap it restores the old `keyslots.json` bytes, and only when the file still holds the journal's bytes and the old bytes equal the file inside the moved root. For prune it re-adds nothing, because removed history files are in the old pinned root, but it states that. Add the tests: a lost rewrap race leaves the winner able to publish. Also reuse, do not re-implement, `assertNameUnmoved` / `assertNameStillAt` (`name-recheck.ts:56-93`) and `createCommitNode.publishRoot` (`commit-node.ts:80-100`).

2. **The republish primitive must also carry 07a's A-01 guards and update `state.rootCid` (1.3, 1.4, 1.6).**
   (a) `publish.ts:288-293` (`assertManifestUnchanged`) and `publish.ts:336-340` read `manifest.enc` before the name start and again after it, and compare bytes. `tasks.md:18` has only "name re-resolve equal to the start". Without the re-read, a publisher that completed between the up-to-date check and the republish is not seen, and the republish publishes a root that holds that device's `manifest.enc` under this device's pin. The primitive needs: read `manifest.enc`, read the name start, re-read `manifest.enc`, compare, then work.
   (b) Rewrap and prune change the MFS root CID. `RootState.rootCid` is "CID last published by this device" (`root-state.ts:36`). Three readers compare it with the node: `publish.ts:123` (`unpublished = state.rootCid !== view.rootCid`, which makes `hasWork` true), `idle-check.ts:60` (the keyless idle path returns undefined, so every timer tick derives Argon2id), and `encrypted-pull.ts:384` (`stateRecordOf` sameRoot). If 1.4 and 1.6 update only the key-slot copy and `keyslotsSha256` (`tasks.md:19`, `design.md:46`), the next publish writes a no-change manifest at sequence+1 plus a history file, on every device, including the timer. This burns the history budget task 1.8 is trying to protect. Change: the `local-updated` step in rewrap and the final step in prune write `rootCid` (new root) into the state with `buildRootState({ ...state, rootCid, keyslotsSha256 })` and `writeRootState`, leaving sequence, `highestSequence` and identities alone. Add a test: publish after rewrap or prune with no change reports "nothing changed" (idle path) and writes nothing.
   (c) Reuse `createSnapshotVerifier` (`read-back.ts:113`) instead of a new read-back: pass the node's current `manifest.enc` bytes and decoded manifest as `SnapshotExpectation`, and the NEW slot bytes as `ReadBackContext.keySlots`. It already refuses extra top-level entries (`read-back.ts:52-62`) and checks the history file for the manifest (`read-back.ts:80-90`), so prune must not remove that file (it cannot: the newest 20 stay).

3. **`keys increase-cost` above the default strands every device that cannot answer a cost question (1.1, 1.4, 2.1, 2.2).**
   `enforceCostPolicy` (`argon2.ts:84-98`) refuses any slot above `DEFAULT_KDF_PARAMS` (65,536 KiB, 3) unless an interactive `approveCost` / `confirmCost` says yes. The plan's "High" preset is 131,072 KiB, 4 (`design.md:43`, open question 7), so after a High rewrap: CLI publish and pull without a terminal refuse (`cli/publish-command.ts:119-128` builds `costPolicy` only when `ctx.io.confirm` exists; `vault-keys.ts:333-343` `pullCostPolicy`); a new or accepting device needs a cost confirmation; and the plugin has none at all: `grep confirmCost|costPolicy|approveCost src/plugin` finds nothing, and `decision-log.md:347` already records "cost-refused key slot (`kdf-cost-refused`) has no confirm dialog". The plugin's unlock dialog and `askUntilAccepted` would show a stop, not a question. Changes: (i) 2.1/2.2 must add a cost-confirm dialog and wire `confirmCost` / `costPolicy` into plugin pull, accept, publish and Restore, or the High preset must be refused in the plugin and the docs (5.1) must say a High vault needs a terminal on every device; (ii) 1.1's rewrap input needs the same `costPolicy` for unlocking the CURRENT slot when it is already above default (`unwrapVckInternal` takes `UnlockInput.costPolicy`, `key-slots.ts:50-57`); (iii) accept-slots (1.2) needs `confirmCost` for an incoming slot above default, besides the downgrade confirmation.

4. **3.1c deletes `tests/helpers/pull-fixtures.ts`, which kept tests and a kept helper still import, and two kept tests import deleted modules (3.1a-3.1c).**

   The v1 route is not only flags and notices. `cli/pull-command.ts:153-216` carries the route choice (`chooseRoute` uses `rootIsEncrypted` from the deleted `pull-screen.ts`), `chooseSelector` with the `text` selector, `assertNoEncryptedOnlyFlags`, `pullWithHost`, `printResult`, `summaryLine`, plus `ManifestError` / `StateError` in `RUNTIME_FAILURES` (`pull-command.ts:9,22,43-44`).

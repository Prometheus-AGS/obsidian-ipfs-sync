## Contract
- The engine asks before any derivation: `approveCost(params)` once per tried slot above the default (`CostPolicy.policy`, unlocking the current slot in prepare/execute rewrap) and `confirmCost(costs)` once for all tried slots (accept). `costConfirmationFrom(ask)` builds both over one asking function; only `true` approves, a rejected or non-boolean answer is a no.
- Costs shown are the engine's `KdfParams` through `describeKdfCost`, next to the default from `DEFAULT_KDF_PARAMS`. No text from the node reaches the dialog, so `escapeForDisplay` has nothing to escape here; every string still goes in through `text` / `setText` (textContent).
- Cancel, Escape and closing the window are a no. A missing or non-finite cost fails closed (confirm disabled, a sentence says why).

## Wired in (2026-10-04, supersedes "Not wired" below)
One `obsidianCostConfirmation(app)` in `src/plugin/index.ts`, handed to every manual path. The "Not wired" section below is history; the three gaps it names are closed.
- Plugin pull and Resolve fork: `PullRunnerDeps.confirmCost` = `.confirm`, passed to `pullEncryptedVault` as `confirmCost` unless the run is `unattended`.
- Restore: the same `confirmCost` reaches `unlockForRestore` (new `RestoreUnlockInput.confirmCost`, passed to `unlockForPull`). Restore has no unattended form.
- Publish: `PublishRunnerDeps.costPolicy` = `.policy`, passed to `publishVault` as `costPolicy` unless the run is `unattended`. In the plugin the unlock that matters is the session's: `createVaultOpener({ costPolicy })` passes it to `openVault`, so the unlock dialog's derivation asks once. The engine then runs with the held vault and derives nothing.
- Timer and catch-up: no confirmation reaches the engine (`confirmCost: unattended ? undefined : ...`, no `costPolicy` when `options.unattended`). The timer never calls the opener (it only reads whether the session is unlocked), so it cannot ask there either. It keeps refusing with `kdf-cost-refused`.
- Engine fix in `src/sync/vault-keys.ts` `pullCostPolicy`: no passphrase means nothing will be derived, so it does not ask. Before this a pull that prompts for its passphrase after a `locked` stop showed the cost dialog first, then the passphrase prompt, then the cost dialog again. Test: "asked once and only once the passphrase is in hand" (fails with two asks if the guard is removed).
- Tests: `tests/unit/plugin-cost-confirm-wiring.test.ts` (14: pull, publish, Restore, each with no port, yes, no, and the unattended path; the engine entry points are wrapped, not replaced, so they run for real at a cheap cost above the default, 19,456 KiB with 4 iterations). Helpers gained optional parameters only: `initVault`/`Rig.init` (kdf params), `pluginOver` (`confirmCost`), `sessionRig` (`costPolicy`).
- Limit: a wrong passphrase on a pull re-runs the engine and asks the cost question again on each attempt. Not fixed (the engine is asked per attempt; the answer is not cached).
- Not verified: the dialog stacked over the unlock dialog in Obsidian, on a phone, and with a screen reader. No Obsidian run.

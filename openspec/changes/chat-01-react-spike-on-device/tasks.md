Planned, not active. Spike on a throwaway branch `chat-spike`; nothing here merges to `main`. Task owners follow the ownership note in `chat-00-phase-overview/tasks.md`.

How to read a task: `(owner)`, `Requires`, `Files`, `Verify` (observable, with command and output or a device-results row). Device checks are run by the operator; an agent cannot run them and must not report them as run. A check with no evidence in `device-results.md` is "not run".

## 1. Spike

- [ ] 1.1 (release-deployment-lead) Spike release procedure. Requires: 07b 4.1 closed (release descriptors), or a documented manual form. Files: `openspec/changes/chat-01-react-spike-on-device/release-procedure.md` (new). Tag form `<manifest version>-chat-spike.<N>`, no `v`, equal to `manifest.json` `version` on the branch (the mobile-feasibility install study: BRAT takes the tag as truth; Obsidian wants tag, release name and manifest version equal); GitHub pre-release; assets `main.js`, `manifest.json`, `styles.css`; one pre-release per spike build; the exact approval point before each create and each delete; a list of created releases kept in `device-results.md` for cleanup. BRAT downloading `styles.css` from a pre-release is documented and never exercised here, so B1 is its first test. Verify: a dry-run plan prints tag, assets and target commit and publishes nothing; the procedure names the approval points; no `gh release create` is run by this task
- [ ] 1.2 (ipfs-engineer) Spike branch and instrumentation. Requires: none. Files (branch only): `src/ui/chat-spike/timing-marks.ts`, `src/plugin/chat-spike-commands.ts`. `performance.now()` marks at the first line of `main.js`, at the end of `onload`, at first chat open and at chat evaluation start and end; a command "Chat spike: show timings" that prints them in a notice and appends them to a note in the test vault; a setting `spikeEvalMode` (`lazy` or `eager`) read at load. No work in the plugin constructor beyond the marks. Verify: stub-obsidian run of the built `main.js` records the marks in order; with `lazy` the chat-evaluation mark is absent after `onload`; with `eager` it is present before `onload` ends

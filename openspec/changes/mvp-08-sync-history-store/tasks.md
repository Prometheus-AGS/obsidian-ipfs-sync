## 4. history command

- [x] 4.1 (data-engineer) `ipfs-sync history [--limit n]`. Requires: 3.2. Files: new `cli/history-command.ts`, `cli/args.ts`, `cli/run.ts` (COMMANDS list and dispatch), `cli/help-text.ts`, tests. Help text states the distinction from `prune-history` (node-side manifest pruning, mutates the node) versus `history` (device-local operation log, read-only). Verify: `node dist/cli/ipfs-sync.mjs history --help` shows the flag and the distinction text; against a seeded fixture database the listing is newest-first, `--limit 1` prints exactly one row, an empty database prints the empty line and exits 0, `--limit abc` exits 2; `--show-request` produces no request trace; the `no-console-log-in-commits` grep over `cli/` prints nothing

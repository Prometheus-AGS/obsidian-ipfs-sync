## CRITICAL
None. No path publishes an object the manifest does not cover without it being in the pinned tree (accepted "pins whatever is in `current/` at snapshot time", W-17); no plaintext path, file name or key reaches the node or any persisted sink; a foreign key is never used for `name/publish`; no downgrade to plaintext publishing exists.

## HIGH
- **W-01 `--repair` is unreachable while a journal exists that resume refuses (permanent lockout, misleading advice).** `publish-session.ts:115-116` calls `resumeJournal(commit, {target, state})` with no repair option. Resume refusals `journal-conflict`, `journal-out-of-step`, `journal-manifest-mismatch`, `sequence-ahead`, `node-manifest-missing` are thrown at `publish-resume.ts:116,122,127-130`; `publish-refusals.ts:82-101` advises `--repair`; `authorizeRepair` (`repair.ts:85`), the only code that deletes the journal for a repair, runs later in `decideSequence` and is never reached because `openSession` throws first. Scenario: crash after `manifest.enc` is written, then the node is put ahead or replaced by a foreign/genuine manifest at the same sequence; every rerun, with or without `--repair`, dies in resume; the only exit is hand-deleting `.ipfs-sync/journal.*.json` (no message may advise it) or abandoning the root. Test gap: "repair drops the journal" tests call `authorizeRepair` in isolation with a damaged `{}` journal (`publish-repair.test.ts:167-180`); `encrypted-publish-repair.test.ts` never touches a journal. Fix: thread `repair` into `openSession`/`resumeJournal`; when `repair` is set and reconcile would throw one of the five codes, do not throw — leave the journal and let `decideSequence`/`authorizeRepair` decide (it checks the node manifest authenticates, same vaultId, keyslots equal local, and deletes the journal only after the checks and confirmation pass); without `--repair` keep the refusals; end-to-end test for each of the five codes (kill after `manifest.enc`, mutate the node, `publishVault({repair:true})` → completed publish or `repair-refused` naming the failed condition).
- **W-02 A planted `manifests/<currentCID>.enc` while the publisher is down locks it out inside resume, before the adopt check.** `publish-resume.ts:95-98` calls `ensureHistoryFile` first; a history file with other bytes that is not our own older manifest throws `history-conflict` (`publish-commit.ts:59-64`); only afterwards is `currentCid() !== manifest.rootCID` checked (the adopt exit). Precondition: node write access (`current`'s CID is public). The journal stays; every run re-throws; the remedy text in `historyConflict()` ("change any file in the vault and publish again") is wrong here (scenario N-01 (b) again). Test `publish-journal-resume.test.ts:163-168` asserts the throw as desired. Fix: in `finishOrAdopt` treat `history-conflict` like a read-back failure — adopt the pending state, delete the journal, let the drift path run at sequence+1; the fresh-publish pre-check in `commitPublish` (`publish-commit.ts:98-99`) then refuses before writing anything, with no journal, and the advice becomes true. Test with a planted history file plus a kill after the manifest write.
- **W-03 `manifests/` growth and junk enforced only in the read-back, after all writes; the decided 1,500/2,000 behaviour is not implemented and task 3.4 is checked done without it.** `grep -rn "1500|prune-history|1_500" src cli tests` finds nothing; the Verify line of 3.4 is met by nothing. `assertRootLayout` (`node-reader.ts:142-149`) and `loadView` never list `manifests/`; the first listing is in read-back (`read-back.ts:67`) after the journal, `manifest.enc` and history file are written; at the 2,001st entry `ipfsLs` throws `KuboResponseTooLargeError` (`node-calls.ts:69-71`) which is not a `ReadBackError`, so `finishOrAdopt` (`publish-resume.ts:108-110`) rethrows — the journal stays and every rerun repeats it. A single junk name (`manifests/x`) gives a `ReadBackError` at `read-back.ts:69`; the next run adopts, `hasWork` is true because the root CID changed (`publish.ts:57`), writes sequence+1 and fails again; the plugin timer repeats every interval, each attempt writing a MB-scale `manifest.enc` and history file; the tool never removes anything from `manifests/`, so the attacker's trigger is permanent (needs only node write access or one stray file). Same class: more than 2,000 entries planted in one prefix folder makes `listCurrentBlobs` throw. Fix: add `manifests/` to the read-only inspection (`RootInspector.view()` or a new `history()`) before any write — list once, refuse with a typed message on any name that is not `<cid>.enc` or not a file, warn at 1,500, refuse at 1,999 naming `ipfs-sync prune-history` and saying junk must be removed on the node; make `KuboResponseTooLargeError` at read-back a `ReadBackError` (or adopt on it) so a journal can never wedge on a cap; guard `hasWork`'s "root CID changed but nothing to publish" case against looping on a permanent read-back failure (refuse from the pre-flight before publishing); reopen task 3.4; tests at 1,499/1,500/1,999/2,000 entries, junk name, planted 2,001-entry prefix folder.

## MEDIUM
- **W-04 A non-authenticating or absent `manifest.enc` is a dead end even with `--repair`, and a torn write can cause it without an attacker.** `assessNode` (`publish.ts:32-33`) and `reconcile` (`publish-resume.ts:124`) call `decodeManifest` and throw a raw `CryptoError`; `planRepair` (`repair.ts:54`) refuses when the node manifest does not authenticate; `node-manifest-missing` is not repairable (`repair.ts:51-53`, misleading "sequences do not need repairing"). Torn write: `files/write` of a multi-MB `manifest.enc` can be cut mid-body (kubo keeps what was written and flushes on close, as far as the reviewer knows); `commit-node.ts:37-40`/`chunked-write.ts:58-69` write in place, not atomically; the kill matrix only kills after a completed request. `keyslots.json` has the same theoretical risk (`vault-mismatch` forever). Only exit today: abandon + full re-upload. Fix: allow `--repair`, with confirmation, when local state or journal exists and the node's `keyslots.json` equals the local copy byte for byte, even if `manifest.enc` is absent or does not authenticate; keep refusing when slots differ; better for torn writes: on resume, if the node's `manifest.enc` fails to authenticate and the journal exists, re-encrypt `journal.pending.manifest` and rewrite it; test with a truncated `manifest.enc` after the journal.
- **W-05 Lock: takeover race, `assertHeld` cannot see a lapsed heartbeat, and the "never the reverse" claim is false.** Takeover (`publish-lock.ts:89-94`, `publish-lock-file.ts:57`): `takeOver` re-reads the token then calls an unconditional `remove()`; two takers that saw the same stale token each remove, the second removing the first's fresh lock → fix: take over by renaming the stale file to a unique name and verifying the moved file's token, or serialise with a second `wx` guard file. `assertHeld` (`publish-lock.ts:132-134`) returns a cached flag updated by the 60 s beat; after a laptop sleep > 15 min another process can legitimately take over and the first resumes writing → fix: throw when `now - lastSuccessfulBeat > 2 × LOCK_HEARTBEAT_MS`. `isStaleLock` (`:71-74`): "same host and pid dead" is unsafe when default host names (`localhost`, `ubuntu`, `DESKTOP-…`) collide across machines/containers sharing a synced `.ipfs-sync/`; the comment "PID reuse can only make a stale lock look live, never the reverse" is wrong unless host identity is unique → add a random per-installation id (or boot id) to the lock. Plugin runner takes no file lock (in-process only, `publish-runner.ts:107`); local state and journal writes are not preceded by `assertHeld`.
- **W-06 Plugin memory and cap claims.** `requestUrl` buffers the whole response before `Response` exists (`request-url-transport.ts:33-41`); the 1 MiB/2,000-entry and 64 MiB caps bound only what the code keeps after the whole body is in memory — a hostile node can OOM a phone; the statement is missing from the threat model (only "binary bodies unverified" in design.md:162,179) → add to the threat model and DESIGN §8 (task 5.1). Unbounded reads: `readDetail` calls `response.text()` on every non-2xx (`kubo/http.ts:38-48`); `rpcCall` without `maxResponseBytes` uses `response.text()` (`rpc-call.ts:106`) for `key/list`, `pin/add`, `name/publish`, `key/gen`, `files/rm`, `id`; `fetchGatewayBytes` (pull v1) reads a whole body → pass a small cap (e.g. 64 KiB) to all RPC calls except `files/write`, bound `readDetail`.
- **W-07 Argon2id runs on every publish, including idle timer ticks, because unlock comes before change detection** (`publish-session.ts:108`). Fix (carried to 4.2/4.3): keyless idle fast path in `publishVault` — before unlock, scan and delta against the state (`planDelta` needs no keys) and `files/stat` the MFS root; if no changes, no journal, no `--repair`, key exists and root CID equals `state.rootCid`, return `unchanged` without deriving (a matching Merkle root proves the node holds what was last published); session-provided unlocked keys (4.2) still bypass Argon2 for real changes.

## LOW
- **W-08** `isMissingPathError` (`kubo/errors.ts:59-61`) matches `/does not exist|not found|no link named/i` on the whole message (incl. URL and node detail) for any HTTP status; a proxy 404 or hostile node reads as "absent". Restrict to the node's own JSON `Message` on 500.
- **W-09** Read-back reads `manifest.enc`, the history file and `keyslots.json` with the 64 MiB cap (`read-back.ts:63,107-108`) although the expected bytes are known → pass `expected.length` as the cap.
- **W-10** `key.ensure()` in `openSession` (`publish-session.ts:115`) runs `key/gen` before resume, without `beforeWrite`, without checking `journal.key === target.key`; a refused run can leave a new key; no `name/publish` re-check after a long run (a key swapped on the node between `keyList` and `publishRoot`) → `keyList` immediately before `publishRoot`.
- **W-11** Local `kv.set` (`cli/node-host-bridge.ts:126-132`) writes state, journal and key-slot copy with default mode and no `fsync`, fixed temp name; state/journal contain every vault path in plaintext → 0600 files, 0700 `.ipfs-sync`.
- **W-12** `IpfsSyncPlugin.passphraseSource` and `allowPlaintextV1` are public mutable properties (`src/plugin/index.ts:42,44,52,59`); any other plugin can read/set them. 4.2 must replace `passphraseSource` with a closure-held session; make `allowPlaintextV1` private.
- **W-13** CLI prints `error.message` raw (`publish-command.ts:159`, `pull-command.ts:132,136`); `KuboHttpError` embeds up to 200 characters of node text → strip control characters once in `io.err`.
- **W-14** Untouched blobs are never re-verified; a node writer can replace one between plan and snapshot (`driftSuspected` compares only the tree CID, `publish-plan.ts:53-57`); readers fail AEAD per file. Accepted by the spec; the CANNOT list must say "silent per-file corruption of unchanged files by a node writer is not detected by the publisher"; consider `--verify-node` later.
- **W-15** Mass removal is silent (`publish.ts:171-172` only refuses the first publish and repair) → add a mass-removal guard (e.g. > 50% of entries or all entries) before the fixture-marker guard is lifted.
- **W-16** Plugin `readRange` re-reads the whole file per segment (`obsidian-fs.ts:107`); a file over 8 MiB edited during upload can be uploaded as a mix of versions; self-heals on the next mtime change.
- **W-17** Dead plaintext-path code: `writeFileToMfs` (`chunked-write.ts:36-51`) has no caller and its error label is the local vault path → delete.
- **W-18** `acquirePublishLock` propagates a raw `EPERM`/`ENOTSUP` from `link()` on filesystems without hard links (FAT, some network mounts) as an uncaught exception → typed message.
- **W-19** Test weaknesses: the rig runs `concurrency: 1` (`publish-rig.ts:113`); kills only after a completed request with single-request blobs (no torn/partial multi-segment blob); loose regex alternations at `read-back.test.ts:74,94`, unrelated final assertion at `:130`; `kubo-bounded-reads.test.ts` fixtures encode the same beliefs as the code.

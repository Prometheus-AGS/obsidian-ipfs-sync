## New findings
### HIGH
- **N-01 Resume and drift have undefined outcomes that lock the publisher out** (encrypted-publish "Interrupted publishes resume"; design §4 steps 1, 3, 6, 7). (a) Anyone with node write access can add one object under `current/` while the publisher is down; read-back then fails, the journal stays, state stays at N, the node is at N+1 and the drift path never runs — permanent self-lockout with an attacker trigger. (b) A kill between the `manifest.enc` write and the history write leaves no history file, and the journal holds only a ciphertext hash, so it cannot be regenerated. An attacker cannot make a resume publish attacker-chosen content (hash equality + Merkle-pinned rootCID); the attack is lockout. Fix: on hash match, decrypt and require vaultId, sequence, rootCID and the file map to equal `journal.pending`; if `manifests/<rootCID>.enc` is absent write it from the node's `manifest.enc` bytes, if present with different bytes refuse; if `current`'s CID ≠ `manifest.rootCID` or any read-back check fails, adopt `journal.pending` as local state at the journal's sequence, delete the journal and run the normal drift path at sequence+1; never leave a journal that blocks the drift path; write order `manifest.enc` THEN history.
### MEDIUM
- **N-02 Replay of an older genuine `manifest.enc` locks the publisher permanently** ("Remote behind"; also the restored-backup "ahead" case). Fix: explicit `--repair` allowed only when the node's manifest authenticates, has the same vaultId, `keyslots.json` equals the local copy, and the sequence is below (behind) or local state is missing/older (ahead); it runs the drift path and publishes at max(local, node)+1.
- **N-03 Drift path is cost amplification** (any write into `current/` forces a full re-encrypt/re-upload: ~1 GB per publish for the real vault, pinned forever; unsafe with a second publisher — device B's in-flight blobs look "unnamed" to device A). Fix: diagnose first (one `files/ls -l` of `current` and its prefix folders vs `state.manifest.files[*].cid`); rewrite only missing/mismatching blobs; remove only names matching `^[a-z2-7]{2}/[a-z2-7]{52}$` not in the new manifest, leave everything else as an anomaly; full re-encryption only when diagnosis cannot establish state; non-interactive full re-upload over 256 MiB needs a flag, interactive confirmation; removal never touches `manifests/`, `keyslots.json`, `manifest.enc`; mvp-07 handoff item 4 adds a multi-publisher guard.
- **N-05 Read-back does not verify what is actually published** (tautological for `current/`: `manifest.rootCID` was taken at step 6, after any planted object; top level and `manifests/` never listed). Fix: list the immutable root one level and require exactly `{current, manifests, manifest.enc, keyslots.json}`; list `manifests/` and require every name `<cid>.enc`; `files/ls -l` the prefix folders touched in this run and require each written blob's CID to equal the CID recorded at write time; `pin/add` and `name/publish` use exactly the verified root CID string, never the MFS path; threat model: untouched blobs are not re-verified per publish.
- **N-06 Canonical-passphrase rule inconsistent between spec and design** (spec folds case and strips separators with no length, silently reducing entropy of e.g. `Correct Horse Battery Staple`). Fix: folding applies iff, after removing U+002D and U+0020, the text is exactly 25 characters each in `[A-Za-z2-7]`; otherwise case and separators are preserved; KAT + test.
- **N-07 User-chosen policy loopholes** (a data blocklist cannot enumerate repetition: `Abcdef1Abcdef1Abcdef1`, `Summer2024!Summer2024x` pass; character classes undefined for non-ASCII; `Passw0rd` evades; `--init` with env counts as the acknowledgement). Fixes proposed: algorithmic repetition rule, Unicode-category classes, leet-folded blocklist, separate `--own-passphrase-ack`. Arithmetic check: 25 × log2(32) = 125 bits, `byte & 31` unbiased; the alphabet is NOT fully unambiguous (S/5, Z/2, G/6, I/L remain) — do not say "unambiguous".
- **N-08 A path still runs the KDF on node-supplied parameters; "no local copy" cases undefined** (slots present, `manifest.enc` absent, no local copy → the publisher may run up to 2 Argon2 derivations on attacker parameters). Fix: store `keyslotsSha256` and `vaultId` in state v2 and the journal, refuse before any KDF on mismatch; with no state, no copy, slots present and no `manifest.enc`, refuse before any KDF ("use a new MFS root or `--recover-slots` with confirmation"); recovery flags show the cost first.
- **N-09 Commitment and wrap key not byte-exact** (construction is sound; the `params` encoding in the commit info is undefined). Fix (freeze before 2.1): `commitInfo = "ipfs-sync/slot/commit/v1" ‖ slotId(16) ‖ v(u32) ‖ m(u32) ‖ t(u32) ‖ p(u32) ‖ dkLen(u32) ‖ salt(16)`, HKDF length 32 with salt `vaultId`; order: validate fixed fields and bounds, Argon2, HKDF commit, constant-time compare, HKDF wrap, AES-GCM; fixed-output KAT; the test-only `unwrap-vck` hook calls the same internal function and a test proves it fails on a corrupted commitment; optionally add `type` and `wrap.alg` to the commit info.
- **N-10 Manifest caps inconsistent, unenforced on the write side, serialisation undefined.** (a) ~330–400 B per entry × 100,000 = 33–40 MB > the 32 MiB cap; (b) a writer whose vault exceeds the caps writes a manifest it can never read back → the writer checks every cap before writing any blob and refuses with a typed message; (c) canonical serialisation: `JSON.stringify` after sorting keys by UTF-16 code-unit order, no whitespace, or drop the reject-noncanonical rule for the AEAD-authenticated `manifest.enc`; (d) the operator's ~1 GB vault (5,000–20,000 entries → 2–7 MB) is well under all caps, but each publish adds a full `manifest.enc` + history copy pinned forever (~4–14 MB) — say so in Risks; (e) make caps consistent (64 MiB or 60,000 entries) and add a test.
- **N-16 Task ordering/gating can let security-relevant code land without review.** Add "Requires 2.5 closed (review-2.md, no open CRITICAL/HIGH)" to 3.1–3.4; move 3.4 before 3.2 (the S-11 window); add a second independent review point after 3.1 and 3.2 (`review-3.md`) before 4.x; "6.2 requires 5.2 closed"; the reference decryptor is written or cross-checked by ipfs-engineer, and security-reviewer diffs it against the spec at 2.5.
### LOW
- **N-11** Local state (`state.json`, `journal.json`) is plaintext at rest: document `.ipfs-sync/` as "exclude from third-party sync"; journal stores hashes where possible.
- **N-12** Lock file: exclusive create (`wx`), heartbeat every 60 s, stale only if no heartbeat for 15 min AND pid dead on the same host, documented `--break-lock` with confirmation.
- **N-13** Test-hook isolation: unique sentinel string in every test-only module + grep built bundles; esbuild metafile assertion that no `src/crypto/testing/` input is in the CLI/plugin graph; lint rule; inject randomness by parameter, no global setter.
- **N-14** Feature operation: confirmed it never writes hostile objects to the shared node (stub + forwarding-only proxy); harden: proxy allowlist of `/api/v0` paths and demo-root arguments; assert the effective API URL is the loopback stub before each child spawn and ignore user/project config; `--cleanup` validates runid `^[a-z0-9-]{8,}$`; never print the generated passphrase; a dropped connection mid-`files/write` can leave a truncated blob under the demo root (acceptable, document).
- **N-15** Threat-model wording: replace "real notes do not leave the device in any form" with "this tool refuses to publish a vault lacking a `fixture` marker; anyone who can create the marker can override this"; the publisher pins whatever is in `current/` at snapshot time; "encrypted at rest" applies to node objects only; do not call the alphabet "unambiguous".
- **N-17** A rename re-encrypts and re-uploads the whole file (name-bound AAD); `encryptedSeen` is lost if `.ipfs-sync/` is deleted; Windows has no POSIX mode check for the passphrase file (refuse symlinked/foreign-owned files); confirm `crypto.argon2` availability in Node 24.15.

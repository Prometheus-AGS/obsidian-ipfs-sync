# Security review 0.1 — mvp-06-encrypted-vault-publish (independent)

Reviewer: security-reviewer; scope: spec/design/tasks only, no code executed.
Saved by the lead as a condensed record of the reviewer's report (2026-09-30). Every finding id, its location and its fix is kept; the reviewer's step-by-step attack narratives are shortened. The full report is in the session transcript.

VERDICT: PROCEED-WITH-FIXES — no plaintext can reach the node while the fixture guard holds, but the artifacts contain a KDF/passphrase decision that cannot be undone later, a publisher lockout bug, unbounded remote-input handling, and unauthenticated or unspecified bindings that must be settled before the formats freeze.

No CRITICAL finding is raised only because the marker guard keeps real data off the node. S-01 and S-02 become CRITICAL the moment the guard is lifted unchanged.

## CRITICAL
None as of this change (see S-01, S-02).

## HIGH
- **S-01 Argon2id cost cannot be "raised later by rewrap"; passphrase policy too weak for a public slot.** Old roots stay pinned and fetchable forever, so an old slot copy keeps opening the same VCK; a 16-character length-only rule admits `passwordpassword1`. Fix: reverse the "keep 19 MiB/t=2" decision — default m=64 MiB (65,536 KiB), t=3, p=1, ceiling m ≤ 131,072 KiB; measure on a phone first; generated passphrase by default (≥ 6 words from 7,776 or ≥ 20 random characters); user-chosen only behind an explicit "attackable offline" acknowledgement plus a small blocklist/pattern rejection; state that a rewrap/passphrase change does NOT revoke old passphrases or old slot copies (only re-encrypting under a new VCK does), in spec and threat model.
- **S-02 Publisher locks itself out after its own failures.** A timeout after the `manifest.enc` write leaves local state at N while the node has N+1, so every rerun refuses ("another device has published"); "interrupted first publish" vs "second devices cannot publish yet" contradict; the StateError text tells users to delete state.json, which guarantees the refusal. Fix: local journal `pending:{sequence, manifestHash, rootCid?}` written BEFORE the manifest write; resume when the node's authenticated manifest matches the journal; define "new device" = no local state AND no local slot copy for this root AND `manifest.enc` present; add the "keyslots present, manifest.enc absent, local copy same vaultId → resume" scenario; fix the StateError text; tests killing after each step of Decision 4 step 5 then rerunning.
- **S-03 Remote objects fetched and parsed with no size bound before authentication.** Fix: `files/stat` first and refuse by size before reading; caps keyslots.json 16 KiB, manifest.enc 32 MiB, entry count and total path bytes after decryption; enforce while streaming; cap slots at 8; parse keyslots.json into null-prototype objects; negative tests (oversize, deep nesting, huge slot count).
- **S-04 MFS is mutable; the publisher publishes whatever it holds at snapshot time; unchanged blobs never re-verified.** Fix: at publish start require `files/stat <mfsRoot>/current`.cid == `state.manifest.rootCID` and `files/stat <mfsRoot>`.cid == `state.rootCid` (else refuse or re-encrypt everything); after the final stat and before `name/publish`, read through immutable `/ipfs/<rootCid>/...`: manifest.enc authenticates with the expected sequence, keyslots.json equals the local copy, `current` CID equals manifest.rootCID; only then pin and publish; verify existing history-file bytes equal ours (don't skip); write blobs to a staging name and move, or force the drift path after any interrupted write.
- **S-05 keyslots.json authenticated only by vaultId equality; AES-GCM wrap has no key commitment.** Fix: byte-for-byte comparison of the node's keyslots.json with the local copy (refuse on mismatch; the local copy is authoritative and rewritten; re-check at the S-04 read-back); key commitment: `wrapKey = HKDF(KEK,"…/wrap")`, `commit = HKDF(KEK,"…/commit" ‖ params)` stored and verified in constant time BEFORE the GCM decrypt; exact-match fixed fields (`v==19`, `dkLen==32`, alg strings) and include them in the AAD; freeze now.

## MEDIUM
- **S-06 KDF ceilings are a DoS; no unlock work budget.** Fix: ceilings m ≤ 131,072 KiB, t ≤ 4, p ≤ 1 (noble runs lanes sequentially); try at most 1–2 passphrase slots with a total m×t budget; refuse a device with no local state and a present manifest.enc BEFORE any KDF; confirm when the node's params exceed the local copy's; pass explicit `maxmem` = ceiling.
- **S-07 "Publisher checks manifest.enc" is check-then-act with no compare-and-swap.** Fix: read-back immediately before `name/publish` (as S-04), cross-process lock file in `.ipfs-sync/`, reword the claim to "best effort, not atomic".
- **S-08 Blob AAD does not bind the blob's node name; reader-side manifest checks not normative.** Fix (freeze now): add the 32-byte HMAC name (or full node path) to the blob AAD; normative reader requirements (header fileId == manifest fileId; decrypted sha256 and size match; tree from the authenticated manifest.rootCID; `manifests/<x>.enc` matches its inner rootCID); negative tests swapping/replaying blobs.
- **S-09 Local key-slot copy not bound to mfsRoot; stated recovery contradicts the "node lost slots" rule.** Fix: store as `.ipfs-sync/keyslots.<mfsRoot-hash>.json` (or map in state); apply the rule only where local state says this root held that vault; explicit "abandon this vault and start fresh" action that keeps a backup.
- **S-10 Pull still reads plaintext v1 with no encrypted marker → downgrade.** Fix: latch `encryptedSeen` in local state and the pull record, refuse v1 forever for any root/key/destination that ever held encrypted content; gate the v1 reader behind `--allow-plaintext-v1` for the interim; extend refused paths to `.obsidian/*` configuration.
- **S-11 The fixture marker can be created by pull → shipped bypass of the guard.** Fix: pull-created marker carries a distinct value (`pulled-fixture`) that publish treats as insufficient, or publish refuses when any non-fixture path exists; otherwise re-scope the claim to "user-created marker".
- **S-12 Streaming decrypt contract contradicts itself** (no partial plaintext vs one segment in memory). Fix: iterator yields only authenticated segments; caller MUST treat the file as untrusted until completion with the final segment; pull writes a temp file and renames after completion; remove the "no earlier plaintext" test or rewrite it against the temp-file layer.
- **S-13 KAT plan defects.** (1) RFC 9106 vector uses params below the wrapper's floors → specify an unexported `argon2idRaw` for tests + floor-parameter cross-check against an independent implementation; (2) McGrew–Viega cases 17/18 use non-96-bit IVs → restrict to 13–16 and NIST `gcmEncryptExtIV256`; (3) add a test-only reference decryptor from the spec text using `node:crypto` (no import of src/crypto) plus AAD-component mutation tests; (4) missing vectors: RFC 4648 base32/base64, u32/u64 BE AAD encoding with index > 2^32, fixed-output vectors pinning nameKey/manifestKey/fileKey labels, NFKC-vs-NFC vectors, HKDF wrapper with empty and long info; (5) nonce-distinctness test is weak → add a structural test that no fileKey is reused; (6) missing negatives: segment < 16 bytes, trailing garbage, non-final segment not full-size, zero-length non-final segment, exponent outside 16–24, truncation at every byte boundary, tag length forced to 128.
- **S-14 Ownership/timing of key-handling code.** `vault-keys.ts`, `session-keys.ts`, `encrypted-transfer.ts`, `cli/passphrase-input.ts` handle secrets but are ipfs-engineer's; the single independent review is at 5.2, after formats are declared frozen. Fix: move vault-keys/session-keys to identity-security-engineer or require a named review by that role; add an early security gate after 2.x (formats, KAT, vector files) before wiring in 3.x.
- **S-15 Threat-model overclaims.** (1) "cannot produce a manifest or blob accepted as authentic": any genuine old blob/manifest is authentic (replay); (2) "cannot move a blob undetected": unimplemented/untested here (S-08); (3) "cannot learn the vault key" true only until the passphrase is guessed offline; (4) "tampering detected by AEAD" does not cover deletion, missing objects, extra files, unauthenticated fields; (5) blob size is EXACT (`len − 22 − 28n`), known-length credentials are recognisable; (6) non-extractable keys don't stop another plugin using the same CryptoKey, and the dialog holds the passphrase as an un-zeroable DOM string; (7) exact rollback status: nothing on the read side is enforced in this change (encrypted pull is refused).
- **S-16 WebCrypto availability and mobile timing unverified; no fail-closed stance.** Fix: no fallback when `crypto.subtle` is missing (typed `crypto-unavailable`); tiny HKDF + AES-GCM known-answer self-test on first unlock in each host; record a phone timing before the guard is removed; unlock UI says "keep the app in the foreground" (backgrounded WebViews throttle timers).

## LOW
- **S-17** Encoding canonicalisation unspecified (canonical padded standard base64; lowercase hex; base32 52nd-char canonical form, compare by string equality with the recomputed name; `sequence` integer 1..2^53−1; JSON duplicate keys; segment-size rules: non-final exactly 2^exp, final 1..2^exp, empty file is one segment; `tagLength: 128`, `iv` length exactly 12).
- **S-18** Passphrase input details: strip only the terminating LF/CRLF, never spaces; raw-mode prompt (Ctrl-C/Ctrl-D, terminal restore on every exit path, multi-byte UTF-8 across chunks, backspace over multi-byte chars, paste); `IPFS_SYNC_PASSPHRASE` lands in shell history/CI logs → document, add `IPFS_SYNC_PASSPHRASE_FILE` (0600); vault creation from an env var requires an explicit `--init`; caller wipes byte inputs incl. the NFKC intermediate; upper byte cap on the passphrase at unlock.
- **S-19** Feature-op check (c) needs the raw VCK: specify a test-only hook, not exported from `src/crypto/index.ts`.
- **S-20** `files/ls` depth ambiguity: specify one level of `files/ls` plus the manifest as truth; what a stray file inside a prefix directory does.
- **S-21** Record blob padding as a reserved v2 option; sizes exact (see S-15.5).
- **S-22** Handoff: rewrap generates a fresh salt and fresh wrap nonce; VCK non-extractable after unlock → adding a slot/rewrap needs a second derivation; Unicode normalisation ICU drift across platforms → add a cross-platform vector.
- **S-23** Marker-guard framing (accident guard, not a control) is correct; only S-11 needs fixing.

## Confirmed sound
- No key/nonce reuse across versions (fresh 128-bit fileId per encryption → fresh fileKey; manifest key sees ~2^20 messages).
- Segment AAD (index u64, final flag, 22-byte header, vaultId) defeats truncation/extension/reorder/duplication/cross-file and cross-vault splice within a blob.
- Slot AAD binds vaultId, slotId, m, t, p, salt; floors stop downgrade by parameter substitution.
- Key separation (distinct HKDF infos; vaultId vs fileId salts) creates no cross-use.
- Fail-closed unlock (wrong passphrase and damaged slot are one outcome; local-first unlock sends no request on a wrong passphrase).
- noble Argon2 API matches the spec (`argon2idAsync` t, m, p, dkLen, key, personalization, maxmem, asyncTick, onProgress).
- Layout refusals hold; nothing secret at rest (VCK and derived keys never stored; data.json gains no secret field); names fixed-length (no path-length leak).
- Marker check runs before the passphrase check.

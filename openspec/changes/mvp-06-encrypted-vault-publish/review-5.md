## New findings
- **R5-01 MEDIUM — plugin lock acquisition assumes `adapter.rename` refuses an existing target; unverified.** `src/plugin/adapter-lock-file.ts:36-50`: no token read-back after `createExclusive` returns true; no `writeIfToken`, heartbeat uses raw `writeBinary` (line 60); `assertHeld` only consults the last heartbeat result (`publish-lock.ts:160-161`) so a lost race stays undetected up to 60 s; `obsidian-fs.ts:127` removes the target before renaming. Scenario: where rename overwrites, a plugin publish and a CLI publish both pass the exists check and both write to the node. Fix: read the file back and compare the token after `createExclusive`, release and refuse on mismatch; repeat immediately before the first node write.
- **R5-02 MEDIUM — abandon silently clears the plaintext-downgrade latch.** `isLatched` (`pull-latch.ts:35-38`) looks only at top-level `encrypted-seen.json` and `state|journal|keyslots.<h>.json`; abandon moves exactly those into `.ipfs-sync/abandoned-<h>-<ms>/` (`vault-keys.ts:264-276`), so the destination reads as never having held an encrypted vault. Scenario: abandon, then `pull --allow-plaintext-v1` against an IPNS name an open-write node repointed at a forged v1 root is accepted (CLI only, explicit flag). Fix: `abandonVault` calls `recordEncryptedSeen` before moving, or `isLatched` also counts `abandoned-*`; add a test.
- **R5-03 LOW —** plugin setup guard weaker than `init`: `vault-opener.ts:51-54` refuses only on `keyslots.json`/`manifest.enc`; `init` refuses any entry and re-checks after Argon2 (`init-command.ts:122-130,209`). Mirror the `init` checks.
- **R5-04 LOW —** in-process sync lock held while a dialog is open (`publish-runner.ts:243-250,182-185`), no timeout; pull, abandon and the timer answer busy while a dialog sits open (e.g. backgrounded phone). Run `requireUnlockedSession` before `tryAcquire` (session `single()` already serialises dialogs).
- **R5-05 LOW —** stale held vault causes a "locked" loop: `unlock()` returns the held vault without prompting (`session-keys.ts:221`); if the local slot copy changed on disk, `unlockBytes` throws `VaultKeysError("locked")`, mapped to "Run Publish vault again" (`publish-runner.ts:124`), reproducing the error. On that error call `session.lock()` and re-prompt.
- **R5-06 LOW —** `UnlockedVault` is an unbranded structural type (`vault-keys.ts:89-95`); nothing binds `keys` to `keySlots`, `unlockBytes` (line 161) does not check `keys.vaultId` against the parsed slots. WeakSet brand as for `ParsedKeySlots` plus a vaultId assertion.
- **R5-07 LOW —** plugin lock heartbeat not atomic: `adapter-lock-file.ts:60` truncates and writes in place; a concurrent CLI read can see an empty/partial file → `lock-unreadable`, and the runbook (line 99) then advises `--break-lock`, which would delete a live plugin lock; scratch `.publish.lock.*.tmp` and `.taken` files accumulate after a crash. Implement `writeIfToken` via temp + rename; add a runbook caution.
- **R5-08 LOW —** crashed-plugin lockout cannot be cleared on mobile: per-session host name means a stale lock is never recognised dead; `--break-lock` exists only in the CLI. Add a "Clear stale lock" settings action gated on age.
- **R5-09 MEDIUM (operational) — `name/publish` repoints the IPNS key `obsidian-vault-sync`.** If the key exists, the script proceeds when its ID is in `ownedKeys` of `/tmp/ipfs-sync-feature-ops/config.json` or given by `--owned-key`; each of the four publishes (including killed ones) overwrites the key's IPNS value with an encrypted demo root; if the key is absent it is created and never removed; demo roots are pinned and never unpinned (`--cleanup` does not unpin). Fix: operator OK that the previous pointer (e.g. the mvp-05 plaintext fixture) may be lost; record `name/resolve` of the key before the run and print it / store it in the result JSON.
- **R5-10 LOW —** build-freshness guard compares mtimes of `cli/` and `src/` sources only and `--allow-stale-build` bypasses it; the code that talks to the node is `dist/cli/ipfs-sync.mjs`. Run `pnpm build` immediately before the run and record the sha256 of `dist/cli/ipfs-sync.mjs` in the result file.
- **R5-11 LOW —** the feature-op toolbox evades the test-hook import lint on purpose (`feature-op-mvp-06.mjs:462` builds the folder name as `["test","ing"].join("")`); bundle written outside the repo so nothing ships. Accept and document, or allowlist `tools/feature-op-*.mjs` explicitly in the lint.
- **R5-12 LOW —** `versions.toml` pins only typescript and node; runtime dependency `@noble/hashes` 2.4.0 (Argon2id, SHA-256) is exact-pinned in `package.json` with a lockfile integrity hash but has no `versions.toml` pin (hand-edit only: operator). Reviewer could not verify registry integrity offline. Operator adds `@noble/hashes = "2.4.0"` and runs `pnpm install --frozen-lockfile` and `pnpm audit`.

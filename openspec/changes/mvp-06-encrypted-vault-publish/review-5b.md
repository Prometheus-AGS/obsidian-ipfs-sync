## New findings
- **F-01 LOW —** the policy and the forward path use different URL forms: `proxy.mjs:82` decides on WHATWG-normalised `pathname`/`searchParams`; `proxy.mjs:44` forwards the raw `req.url` (e.g. `//x/api/v0/files/write`, a backslash, `/api/v0/a/../files/rm` normalise differently). No exploitable case constructed (kubo likely fails closed) but not verified. Fix: forward `url.pathname + url.search` from the same parsed URL that was vetted; refuse a `req.url` not starting with `/`.
- **F-02 LOW (latent) —** some check details print unredacted before the passphrase is known: `S.cli("init")` runs `scrub` while `secrets` is still empty (`shared-phase.mjs:39`, `run.mjs:48`); the init check prints `firstLine(init.stderr) || firstLine(init.stdout)` as detail even on PASS and it goes into the result JSON (`shared-phase.mjs:40`); `hostile-phase.mjs:34-44` same ordering. Current CLI does not print it (`init-command.ts:153`); matters only on regression. Fix: no detail for the init check, or re-scrub with the loaded secrets before printing.
- **F-03 INFO —** `name/publish` accepts extra params (`lifetime`, `ttl`, `allow-offline`) unchecked; they do not widen reach beyond the demo key. Unused circular import of `run` from `run.mjs` at `shared-phase.mjs:11`.

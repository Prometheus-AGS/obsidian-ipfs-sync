## Findings
- **C-01 HIGH — publish never wipes the canonical passphrase.** `cli/publish-command.ts:112-125` passes `await ctx.passphrase?.()` to `publishVault` and never wipes it; no wipe in `src/sync/publish.ts`, `publish-session.ts`, `vault-keys.ts`. Spec "Handling in memory" (SHALL overwrite after derivation), task 4.1, README (~165) and help text all claim it. Fix: try/finally around `publishVault` wiping the array; test asserting zeros after success, refusal and throw.
- **C-02 MEDIUM — FIFO hangs the read.** `cli/passphrase-file.ts:52` `open(O_RDONLY|O_NOFOLLOW)` blocks on a FIFO before `isFile()` runs. Fix: add `O_NONBLOCK` on POSIX.
- **C-03 MEDIUM — init "empty root" check narrow, late, not repeated.** `cli/init-command.ts:121-126,157-186`: (1) tests only keyslots.json/manifest.enc while the message says "empty root" (legacy v1 content passes) → check any entry or reword to "no vault"; (2) interactive path shows and re-enters the passphrase before the root is inspected → move the read-only check ahead of `showAndConfirm`; (3) Argon2 gap between check and `writeKeySlotsFile`, and `filesWrite` overwrite semantics unconfirmed → re-run the check just before the write, document the race is narrowed not closed.
- **C-04 MEDIUM — cleanup can delete the passphrase while a local key-slot copy exists.** `init-command.ts:176-183` removes the file on any openVault error; `createVault` runs `persistCopy` before `finish`, so a later throw leaves the copy and deletes the passphrase → unrecoverable orphan (rerun refused by checkLocally). `rm` failure also masks the original error. Fix: delete the file only if no local copy exists (else keep it and say so); swallow `rm` errors; add tests for both failure branches (openVault fails → removed; writeKeySlotsFile fails → kept) plus a failure after the copy write.
- **C-05 LOW —** interrupt/kill between file creation and vault creation leaves an orphan file; message should say "if a previous init was interrupted, delete this file and rerun"; optional SIGINT handler.
- **C-06 LOW — directory checks shallow.** `passphrase-file.ts:114-153`: ancestor symlinks followed; group/other-writable non-sticky parent accepted; parent swap between lstat and open (misplacement, not disclosure). Fix: realpath the directory once and open under it; compare `lstat(absolute)` with `fstat(handle)` dev/ino after create and remove on mismatch; refuse group/other-writable parent without sticky bit; record residual risk in docs (no openat in Node).
- **C-07 LOW — prompt edge cases.** `passphrase-prompt.ts:96-99,113-115`: ESC O + byte (SS3) lets the final byte into the buffer; after overflow/Ctrl-C the rest of a large paste can reach the shell; Ctrl-U/W dropped. Fix: treat ESC O + one byte as a sequence; drain input ~50 ms on termination (optional).
- **C-08 LOW —** Windows wording doubled and printed after the file is written; merge into one sentence, add "the file inherits the folder's access list", optionally warn before writing.
- **C-09 LOW — docs.** README.md:170ff still says publishes plaintext / encryption not implemented (owner: documentation-specialist, task 5.1); add that the interactive init display leaves the passphrase in terminal scrollback and `script`/tmux logs; the env var stays in `process.env` for children.
- **C-10 INFO —** unwipeable strings are only the allowed ones (env string, init display string); `canonicalizePassphrase` (src/crypto) leaves the 2-byte check and digest unzeroed; publish lock is held while the prompt waits (fine at 60 s heartbeat / 15 min stale); Ctrl-C at the prompt exits 1, not 130; `IPFS_SYNC_PASSPHRASE=""` fails as passphrase-format.

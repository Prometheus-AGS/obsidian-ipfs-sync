## What is authenticated, and where the history name is trusted
- **Authenticated:** the decrypted `manifest.enc` (`vaultId`, `sequence`, files, `rootCID`, `device`, `publishedAt`), the key slot (by unlock and commitment), each blob (header, AAD, sha256). `--manifest` also checks that the inner `rootCID` equals the named CID.
- **Name trusted without authentication:** lookup of the fork ancestor by prefix; labels in `--list-versions` and the Restore list for entries over 8 MiB; prune ordering and keep-set; the "newest prefixed" probe.
- **Withholding and reordering:** the ancestor is decrypted and checked for `vaultId` and sequence N, so withholding only removes the base (fallback: conflict copies, safe); reordering cannot forge. Real gap: duplicate authentic files at one prefix, and no authenticated parent link (Q-03).

## New findings — 07a
- **Q-01 HIGH — policy-skipped entries are silently dropped from the next manifest that device publishes.** 07a design 7 and 11; `src/sync/diff.ts:96-102` and `src/sync/publish-plan.ts` (`kept` is built from the baseline only). Linux publishes `CON.md` or `Note.md` and `note.md`; a Windows or macOS device skips them (path policy applies in the pull only; "a policy-skipped path is not in the baseline"); that device publishes; the new manifest is `kept` plus `writes`, so the skipped entries vanish from the vault for everyone, blobs orphaned; a new device restoring from the name misses the files. Only the incomplete-pull block stops this and `policy-skipped` explicitly does not block; the mass-removal guard fires only above 50%. Fix: keep every node-manifest entry this device could not materialize (`policy-skipped`, `unfetched`, `integrity-failed`) in the baseline flagged `unmaterialized`; publish copies them unchanged and counts their blobs as named in the drift check; test: Linux-only `CON.md` survives a Windows-device publish; state whether the fold-aware exclusion matcher in task 3.1 changes what the publisher excludes.
- **Q-02 MEDIUM — a node can force permanent `complete:false`, with no way out.** design 7 and 14. A gateway that answers 200 to Range, for a file over 32 MiB in the plugin, leaves that file `unfetched` on every pull; publish stays blocked indefinitely; the 404 case is the same. Fix: the Q-01 carry-forward removes the need to block for these paths; otherwise a documented per-path local exclusion, or a `--publish-despite-unfetched` path with confirmation.
- **Q-03 MEDIUM — the fork ancestor is not authenticated as the parent.** design 9; history-naming. A fork leaves two history files with the same prefix; a node (or an old fork) picks which genuine sequence-N manifest is the base; if that base equals the local edit, `L==B` and R is replaced with no conflict copy. Fix: persist the identity of the manifest this device built on (`previousIdentity`) in the state at publish; use an ancestor only if its identity matches; use none if the prefix is ambiguous; test the duplicate-prefix case.
- **Q-04 MEDIUM — name re-check is taken at run start, not against the root the journal was built on.** design 10.3; task 2.2. A crashes after writing its pending manifest; B publishes; A reruns; `startRoot` is now B's root, the re-check passes, and A adopts and republishes over B. Neither the 2.2 tests nor the up-to-date rule covers it. Fix: store the resolved root in the publish journal when the pending manifest is built and compare against it on resume; add a crash, foreign publish, resume test that must end in a fork or refusal.
- **Q-05 MEDIUM — the plugin floor can regress.** design 3; task 1.2. The floor lives in `data.json`; a settings save from a stale in-memory copy overwrites the `deviceStore` section. Fix: a single writer for `data.json`; floor writes as read-merge-max; a test that settings saves never lower a floor.
- **Q-06 MEDIUM — the Restore list shows unauthenticated names for entries over 8 MiB.** plugin-pull-ui "Restore". Fix: the confirm dialog shows the authenticated sequence and date from the loaded manifest and refuses if they differ from the chosen label.
- **Q-07 MEDIUM — `--repair` ahead remains for "no usable baseline" (design 10.1).** Deleting `.ipfs-sync/` or running `abandon` leaves a slot copy and no state; `--repair` then publishes at node+1 from the local copy, dropping remote-only files, and 07a has no mass-removal guard. Fix: refuse when the floor for that `vaultId` exists (pull first); permit only for an undecodable state with explicit confirmation.
- **Q-08 LOW —** format 3 decoder strictness: require every new field with no defaulting, `complete` strictly boolean, `manifestIdentity` 64 hex, and `highestIdentity == manifestIdentity` when the sequences are equal; tests for a v3 file missing `complete`.
- **Q-09 LOW —** the 8.3 short-name rule is undefined (only `OBSIDI~1` is in the vectors; `GIT~1` and `IPFS-S~1` are not): give a regex; honest names like `abc~1.md` are refused as `unsafe` and exit 1.
- **Q-10 LOW —** upgrade-day removal of `.obsidian/*` entries counts toward the 07b mass-removal guard; a small vault can exceed 50% and the message blames an unmounted vault: count exclusion-driven removals separately.
- **Q-11 LOW — plugin fetch and temp-file nits:** cap the header exponent from below (exponent 16 means 16,384 requests per GiB); the plugin-load sweep can delete the `.part` files of a concurrent CLI pull (sweep only under the lock or only older files); if a conflict copy cannot be written (e.g. name too long) abort the replace; render node text via `textContent` only; no clipboard-copy control on mobile.
- **Q-12 LOW —** a key holder can ratchet `highestSequence` to 2^53-1, blocking all later publishes on every device; the only recovery is deleting the per-user floor store: name that as the documented recovery.

## New findings — 07b
- **Q-13 HIGH — the git-history binding (form a) dead-ends on the first defect-loop iteration.** guard-evidence Item A(a) "exactly one commit E"; design 9. The defect loop is the expected path (the first real Obsidian run will likely find something); the fix changes T; re-issuing `review-final.md` gives it a second commit, so (a) fails permanently unless history is rewritten. Form (b) does not have this problem. Fix: bind to the last commit touching the file, or to a per-tree file name `review-final-<T8>.md`; drop "exactly one commit". Related: task 6.5's "lead's disposition recorded" must land in the same commit.
- **Q-14 HIGH — the trust anchor for the SSH form is chosen by whoever invokes the checker.** design 9; guard-evidence Item A(b). `IPFS_SYNC_ALLOWED_SIGNERS` and `--allowed-signers` let the agent team create its own key and allowed-signers file, sign the record, and pass; only the printed fingerprint differs and nothing compares it to a known one; the unsigned form (a) needs no secret at all. Also missing: `ssh-keygen -Y verify` needs `-I <principal>` and `-s`; pin `namespaces="ipfs-sync-review"` in the allowed-signers entry. Fix: a fixed operator-owned path in the per-user directory with owner and 0600 checks, not inside the repo; `release-mvp-07 record` refuses env and flag overrides; enrol the fingerprint through a TTY step; print the fingerprint in the release notes; for the unsigned pass require a TTY-typed operator acknowledgement at `record`; state that the key must not be agent-readable (passphrase or hardware key).
- **Q-15 MEDIUM — files ignored by git bypass T but are still compiled by the in-place build.** guard-evidence "Tree hash" and "Build hashes"; `.gitignore` line 2 is `main.js` (matches at any depth): a `src/**/main.js` is neither tracked nor untracked-not-ignored, so invisible to T but compiled by `pnpm build` in place. Fix: require `git ls-files --others --ignored --exclude-standard` to be empty inside the scope; build from a clean export of `reviewedCommit` (`git archive` or a fresh worktree) with a scrubbed environment; take the file set from `git ls-tree HEAD -z` and compare worktree bytes to the blobs; require the index to equal HEAD and ignore `assume-unchanged`/`skip-worktree` flags; hash blob bytes, not the `.gitattributes`-filtered worktree.
- **Q-16 MEDIUM — the review-to-tree binding is the lead's assertion.** The reviewer role is read-only and cannot compute T or B. Add a coverage list (path, read yes/no) to the record keyed to `--print-tree-hash --list`; the checker requires every `src/`, `cli/` and scoped `tools/` file to be covered or declared unread.
- **Q-17 MEDIUM — the audit allowlist is hard-coded in the checker, which is inside T.** Item E. A new advisory, including one on a dev-only dependency, forces a lockfile or checker change, changing T and sending you through the full loop. Fix: audit with `--prod`, or split dev advisories out; take the accepted advisories from dated `accepted` findings in the review record; evaluate the result at `record` time, not T-bound.
- **Q-19 MEDIUM — the maintenance journal can dead-end, and resume has no phase marker.** 07b design 2 and 4; key-management. Lost race: after a lost rewrap race the node file matches neither the journal nor the old bytes, resume says "refuse", and publish and pull refuse while the journal exists. Crash after `name/publish`: a phase-less resume reruns `republish-root`, whose name re-check sees its own publish and refuses. Fix: record a phase in the journal; treat name == snapshot root as done; `keys accept-slots` or `keys discard` clears a stale journal; the refusal message names that command.
- **Q-20 LOW —** prune needs a history-withholding check: require the newest history entry's sequence to equal the node manifest's sequence; count duplicate prefixes.
- **Q-21 LOW — Item E test-run weaknesses:** require zero `skip`/`only`/`todo`, a minimum test count per named file, and a zero-match guard; record node and pnpm versions and put `.npmrc` and the engine pin in scope; docs are outside T so a post-review README can overclaim.
- **Q-22 LOW — phone and operator-run nits:** the TTY nonce blocks pipes, not pty automation; typing a 64-hex hash from a phone screen is error-prone; the operator-run script should run the checker's build, not just hash the existing `dist/`, so a stale `dist/` fails early.
- **Q-23 LOW —** overlap with publish: `keys accept-slots`, rewrap and prune should take `publish.lock`; rewrap and prune snapshot the shared MFS tree and are overlapping-publish vectors.
- **Q-24 LOW —** dead end when the checker fails: it exists, but is expensive and undocumented in one place; the operator's only route is fix, new T, re-issue record, re-run the operator run, re-measure the phone if `main.js` changed. Require running the checker's `plan` (items A, C, D, E) before the long operator run, and document this sequence in the runbook.
